Scope for this contribution wave

This wave repairs behavior Miles already has: lock lifecycle, metric reduction, gradient ownership on the shipped OPD advantage path, the external scorer transport, and the response-wide Top-K candidate union. It introduces no trainer-side targets, no new loss, and no algorithm-level change. Trainer/backend extensions, SGLang changes and multimodal scoring are outside this wave.

3 · Scorer contract: bound the existing transport

The official OPD scorer constructs a new HTTP session for every request and asks the external teacher server to return log-probs from the start of the sequence, although training consumes only the response window. It also sends every sample's request at once, with no deadline, no retry policy, and no check that returned scores line up with response tokens.

Before O1

new session→ prefix + response→ full logprob reply

Correct scores can be extracted, but transport setup and response volume repeat per sample, and a shifted reply would be trained on silently.

With the contract

shared client→ bounded RPC→ response window

Same scoring semantics through the repository's shared HTTP client, with an in-flight bound, one deadline shared across bounded retries, and a strict one-score-per-token alignment check.

Scope boundary

The scorer PR does not change what is scored or how scores are used. Its claim is narrow: an external scoring request has a bounded transport lifecycle and returns exactly one finite score per response token, or fails loudly with the sample's identity. The response-window request follows the same convention the repository already uses for prefill scoring. A speedup is the experiment hypothesis, not a statement baked into the PR.

4 · O2/O3: bound the shipped Top-K rescoring path

The official example uses --opd-log-prob-top-k 16. In both native one-sided strategies, one model owns a per-position candidate matrix [T,K] and the opposite model must supply log-probs for those exact token IDs. The existing SGLang request accepts one arbitrary-ID list, so Miles currently unions candidates across all T response positions into U and receives T×U cells. A long response can make U large enough that JSON construction, transfer and server-side materialization dominate or fail.

Legacy global union

native [T,K]→ global union U→ reply [T,U]

The objective consumes K values at each position, but the response carries every ID in U at every position. Worst-case candidate cells grow toward T²K.

O2/O3 behavior

blocks [B,K]→ local Ub→ compact [T,K]

Each request covers at most B adjacent positions and only their local union, where |Ub|≤BK. Miles validates token alignment, gathers the K required values per row, discards the Cartesian block reply, and preserves the original scalar computation.

Two implementation items, one PR

O2 establishes candidate locality: validate each native Top-K row, divide response positions into deterministic blocks, and cap each request's union at the block boundary. O3 wires the same scorer into both directions: only-student sends student candidates to the teacher; only-teacher obtains teacher native Top-K once, then sends those candidates to the student router. The other strategies retain the legacy path in this PR.

Explicit non-goals

No new Sample fields, trainer-side loss, backend collective or SGLang patch. The block-size flag defaults to 32 and 0 restores the legacy global union for controlled comparison. Smaller blocks reduce candidate replies but increase request count and repeated input-ID transfer; sequential prefixes are expected to benefit from SGLang's existing prefix cache, which is an experiment item rather than a correctness assumption.

6 · Controlled experiments

The scorer-contract and top-k-repair PRs warrant cluster evidence; the three bug fixes are fully covered by fast tests. All runs use the official math OPD example with a 32B teacher and 8B student. The environment, teacher-serving runtime, teacher endpoint, data order, seed, parallel layout and token budgets are frozen. The script remains examples/on_policy_distillation/run-qwen3-8B-opd.sh; environment overrides select only the named strategy and block-size treatment.

Results for the B pair (only-student) are in: Position-blocked top-k OPD scoring — A/B evidence. Summary: with short responses both arms complete 6/6 steps and position blocks cut per-step wall clock from ~290s to ~108s (2.7×, teacher prefix-cache hit 6.7% → 97.5%); with the example's default (thinking) template the legacy global-union arm does not finish step 0 within the configured deadline — a single 8,883-token request exceeds 600s — while position blocks score 9–16k-token samples in the tested run (38,932 block requests, zero failures, two steps completed). The corresponding only-teacher C0/C1 pair remains pending.

7 · Execution protocol

The fork is both the development remote and the first review target. A clean contribution checkout prevents private history, scripts or experiment artifacts from leaking into upstream patches.

1. Freeze the base

Fetch ChenyangWangjohn/miles-fork:main and radixark/miles:main; verify the fork base is current, then record the Miles SHA, environment versions, teacher-runtime identifier and the official example revision.

2. Work in an isolated contribution checkout and environment

Develop in a separate clone with its own cloned environment. Keep the same teacher-serving runtime for every paired run.

3. Re-implement each topic on the upstream tip

Adapt each fix to the current upstream contracts and HTTP utilities instead of transplanting internal patches verbatim.

4. Run local and cluster gates

Fast tests first, then lint and formatting, then the three official-example pairs. A baseline and treatment differ only in source branch for O1, or OPD_TOP_K_SCORING_BLOCK_SIZE=0/32 for O2/O3.

5. Review in the fork

Verify on a work branch, then cherry-pick the reviewed commit onto a clean branch from fork main and open a PR into ChenyangWangjohn/miles-fork:main with commands, exact SHAs and known scope limits.

6. Propose upstream

Open the equivalent branch against radixark/miles:main with Motivation, What's in this PR, Validation and Notes for reviewers. Do not combine unrelated fixes to reduce PR count.
